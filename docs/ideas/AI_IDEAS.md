# 주거 하자 대응 AI 아이디어 비교

11월 22일 시연을 목표로 React Native Expo 앱 1명, FastAPI·Supabase 백엔드 1명, 이미지 인식 1명이 작업한다고 가정한다. 아래는 후보 비교이며 난이도는 작업량 추정이다. **낮음**은 현재 기록과 화면을 재사용하는 작업, **중간**은 화면·데이터나 검증 흐름을 추가하는 작업, **높음**은 외부 접근 권한이나 별도 데이터 품질 검증이 핵심인 작업이다.

> **2026년 11월 20일 MVP 변경 반영**: 분석 페이지의 AI 추가 질문 채팅창을 제거하고, 한 화면에서 사진(1~2장)·위치·재질(+선택 증상 메모)을 일괄 입력받아 심각도(%)·추정 원인·해결방안·재발 방지책을 바로 생성하는 흐름으로 전환했다. 설문/객관식 추가 질문은 추후 논의할 보류 항목으로 두며, 지원 하자 유형은 `크랙·벗겨짐·곰팡이`, 시연 지역은 `용인`으로 확정했다.

## 사진 이후에 AI가 하는 일

| 후보 | 구현 난이도와 작업 | 한계와 검증 |
| --- | --- | --- |
| **새 후보 · 어떤 증거를 더 남길지 안내** | **낮음.** 사진 관찰과 위치·재질 입력을 바탕으로 전체 위치 사진, 근접 사진, 재발 여부 확인 중 가장 필요한 하나를 결과 화면의 `미확인 정보`나 보류 안내로 추천한다. *(보류 중인 설문/객관식 추가 질문을 도입할 때도 연결 가능)* | 사진 한 장에서 면적, 깊이, 원인을 추정하기 어렵다. 같은 근접 사진에 위치·재질을 입력한 경우와 정보가 부족한 경우를 넣어 추천이 달라지고, 이미 제공한 자료는 다시 요구하지 않는지 확인한다. |
| **보내기 전 요청문 검토** | **낮음.** 하자 기록과 초안(임대인 점검 요청문·업체 채팅 첫 문의 초안)을 대조해 누락된 위치나 근거 없는 단정을 표시한다. | 검토 모델도 원인을 지어낼 수 있다. 지적한 문장과 관련 기록을 함께 표시하고, `누수로 생긴 곰팡이`가 `창틀 실리콘 주변 검은 얼룩`으로 바뀌는지 검증한다. |
| **새 후보 · 음성 메모를 하자 기록으로 변환** | **중간.** 녹음·전사 후 위치, 재질, 최초 발견, 재발, 시도한 조치를 추출해 사용자 확인을 받는다. | 날짜, 부정 표현, 방 위치·재질을 잘못 인식할 수 있고 녹음 권한과 지연이 생긴다. `두 번 닦았지만 어제 다시 보였다`를 빠뜨리거나 반대로 기록하지 않는지 확인한다. |
| **새 후보 · 같은 위치의 재발 기록 비교** | **중간~높음.** `내 정보`의 내 하자 분석 기록 목록에서 같은 위치 사례에 사진 두 장과 촬영 일시를 연결하고, 사용자가 위치를 확인하면 AI가 관찰 차이와 시간 순서를 정리한다. | 각도·조명 차이가 커지면 크기 변화를 오인한다. 정량적인 면적이나 악화 여부를 단정하기 어렵다. 동일 사례에 여러 사진을 저장하는 기능과 자료가 필요하다. |
| **임대인 답장 읽기와 후속 초안** | **낮음(붙여넣기) / 중간(공유로 가져오기) / 높음(자동 수신).** 기록과 답장을 대조해 점검 가능일 등 남은 질문을 제안한다. | 카카오톡 공개 API의 개인 대화 수신 조회는 확인되지 않았다. Expo 공유는 사용자 동작과 원본 앱의 공유 지원이 필요하다. 자동 수신이 기능 채택 조건이므로 현재 보류한다. [카카오톡 메시지 API](https://developers.kakao.com/docs/ko/kakaotalk-message/common) · [Expo Sharing](https://docs.expo.dev/versions/latest/sdk/sharing/) |
| **견적서 작업 범위 비교** | **중간(텍스트) / 높음(사진·PDF).** 두 견적의 원인 점검, 제거, 마감 복구 여부를 뽑고 업체 채팅에서 물을 질문을 제안한다. | 명시되지 않은 항목은 `미기재`로 표시해야 한다. 금액만으로 이질적인 작업 범위를 비교하기 어렵고 비교할 실제 사례가 필요하다. 기존 업체 채팅 초안 흐름과는 별개 후보다. |

## 후속 후보: RAG와 MCP

| 후보 | 구현 난이도와 작업 | 한계와 검증 |
| --- | --- | --- |
| **공식 자료 RAG** | **중간.** 검토한 자료를 저장하고, 질문별로 관련 문단을 검색해 원문 링크와 확인할 사항을 제시한다. | 자료가 적고 답이 고정이면 검토한 링크만으로 충분하다. 관련 근거가 없는 질문에서 다른 조문을 억지로 붙이지 않는지, 자료 시행일·갱신일을 확인할 수 있는지 본다. |
| **선택 옵션 · RAG로 증거 추천 보강** | **중간.** 기본안은 사진과 하자 기록(위치·재질)에서 빠진 정보를 보고 추가로 남길 증거를 추천한다. 건물별 접수 안내문이나 공식 안내가 여러 개 확보되면, 해당 사례에 맞는 문단을 검색해 필요한 첨부 자료와 출처를 보여준다. | 건물마다 요구하는 자료가 다르거나 안내가 바뀔 수 있다. 같은 하자라도 안내문에 따라 추천이 달라지는지 확인한다. 해당 자료가 없으면 일반적인 증거 추천을 제공하고, 건물별 접수 요건은 미확인으로 표시한다. |
| **민법 조회 MCP** | **중간, 인증키와 도구 미확보 시 높음.** 읽기 전용 도구로 조문 번호, 원문, 시행일, 출처를 가져온다. `왜 알려야 하나요?`, `누가 비용을 내나요?`에서 근거 사용과 판단 보류를 비교한다. | 조문이 있어도 실제 원인과 계약 내용을 모르면 개별 비용 부담을 확정할 수 없다. 같은 두 조문만 필요하면 링크 방식이 더 간단하다. 법제처 API 또는 커뮤니티 도구의 실제 호출, 결과 누락과 호출 실패 대응을 검증한다. [법제처 API 안내](https://open.law.go.kr/LSO/openApi/guideList.do) · [커뮤니티 MCP 후보](https://github.com/hjsh200219/korea-public-data-mcp) |
| **상담·조정 경로 조회 MCP** | **중간~높음.** 임대인에게 연락한 뒤에도 막혔을 때 공식 경로와 준비 자료를 읽기 전용으로 조회한다. | 지역·사안별 공식 데이터와 연동 수단을 확보해야 한다. 누락이나 중복, 오래된 링크가 생길 수 있다. 검색에 상세 주소, 사진, 대화 원문은 필요하지 않다. |
| **하자 기록 조회 MCP** | **중간.** 사용자 권한을 확인해 선택한 하자 기록의 확인된 사실을 여러 초안 생성 도구에서 재사용한다. | Expo 앱 하나라면 FastAPI 내부 조회로 같은 사용자 경험을 제공할 수 있다. 별도 AI 클라이언트에 도구를 제공할 때 권한 관리와 MCP 도입 비용을 감수할 이유가 생긴다. |
| **새 후보 · 임대차계약서에서 관련 문구 찾기** | **중간(사용자가 제공한 텍스트) / 높음(스캔 계약서).** 수리·통지 관련 문구를 찾아 원문 위치와 확인할 질문을 제시한다. 공식 자료 RAG와 섞어 표시하지 않는다. | OCR이 특약과 체크박스를 놓칠 수 있고 계약서에는 불필요한 개인정보가 많다. 문구가 없거나 읽을 수 없을 때 표시하고, 조항 효력과 비용 부담은 판정하기 어렵다. |

## 시연 조합 제안

- **가장 작은 추가 기능**은 결과 화면 `미확인 정보` 기반의 추가 증거 안내다. 같은 얼룩 사진이라도 근접 사진만 있는 경우와 위치·재질 정보가 함께 입력된 경우의 다음 행동이 달라져야 한다.
- **MCP를 후속으로 검토할 때는** 민법 조회가 우선 후보다. 실제 도구 호출, 원문 출처, 근거 부족 시 판단 보류를 확인한 후 채택한다. 데이터나 연동이 막히면 검토한 원문 링크를 제공하는 방안이 있다.
- **둘을 잇는 시연**은 `사진+위치·재질 일괄 분석 → 심각도%·추정 원인·해결방안·재발 방지책 → 필요한 추가 증거 안내 → 임대인 점검 요청 또는 업체 채팅 → 연락을 권하는 근거`다. 용인의 크랙·벗겨짐·곰팡이 사례로 검증할 수 있으며 기능 채택은 팀 논의 후 확정한다.
