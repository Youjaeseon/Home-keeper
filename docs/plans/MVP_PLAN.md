# 주거 하자 대응 에이전트 · 팀 공유용 MVP 계획

청년 임차인이 집에서 하자를 발견했을 때, 사진과 추가 답변으로 상태를 파악하고 직접 조치, 임대인 점검 요청, 업체 연락 중 필요한 행동으로 이어가도록 돕는다.

## 사용자 흐름

1. 준비된 계정으로 로그인하고 새 하자 기록에 같은 하자의 전체 사진과 근접 사진을 최대 두 장 등록한다. 한 장으로 시작할 수 있으며 두 번째 사진은 선택이다. 선택을 마친 뒤 `분석하기`를 누르면 선택한 사진을 함께 분석하고 채팅으로 이어간다. 부족한 정보는 채팅으로 확인한다. YOLO가 하자 후보를 찾지 못하거나 다음 질문을 정하기 어려우면 비전 LLM으로 한 번 더 분석한다. 사용할 수 있는 결과가 없으면 위치와 증상을 직접 입력한다.
2. 답이 진단이나 다음 행동을 바꿀 때만 한 번에 하나씩 묻는다. 사용자는 언제든 `현재 정보로 결과 보기`를 선택할 수 있다. 답하지 않은 내용은 미확인으로 남긴다.
3. 결과에 관찰한 파손 상태, 심각도, 판단 이유와 다음 행동을 보여준다. 심각도는 `낮음`, `중간`, `높음`으로 표시하고, 정보가 부족하면 `판단 보류`로 표시한다. 재발했거나 원인이 불명확하면 점검을 권한다.
4. 직접 조치를 권하면 결과 화면에 처리 방법과 준비물을 보여준다. 점검을 권하면 `임대인에게 보낼 점검 요청문`을 주 버튼으로 둔다. 요청문에는 집 안의 하자 위치를 넣고, 어느 집인지 식별할 정보는 사용자가 필요할 때 덧붙인다. `업체 찾기`는 임대인에게 연락하기 전에도 이용할 수 있다.

## 업체 찾기와 연락

- 사용자는 검색할 동네를 입력한다. 앱은 사진 분석과 답변으로 검색할 작업을 미리 선택한다. 판단이 어려우면 원인 점검과 추천 이유를 보여준다. 사용자는 필요할 때 작업을 수정할 수 있다.
- 해당 동네로 출장할 수 있고 해당 작업을 하는 업체를 DB에서 조회한다. 결과가 비어 있으면 `샘플` 표시가 붙은 예시 업체를 보여준다. 조회 오류는 별도로 표시한다.
- 후보 목록에서 같은 하자 기록으로 만든 견적 요청문을 복사할 수 있다. 실제 업체에서는 `전화하기`나 `메시지 보내기`로 연락 화면을 연다. 가능한 기기에서는 메시지에 요청문을 미리 채우고, 그 외에는 사용자가 복사해 붙여 넣는다. 전송은 사용자가 확인한 뒤 직접 한다. 샘플 업체의 연락 버튼은 시연 안내를 띄운다.

## 역할과 시연

| 담당 | 작업 |
| --- | --- |
| 앱 1명 · React Native/Expo | 로그인과 하자 기록 입력, 질문과 결과 화면, 요청문 복사, 업체 후보 목록과 전화·메시지 연결 |
| 백엔드 1명 · FastAPI/Supabase | 인증과 기록 접근 권한, 모델 연동, 질문과 요청문 생성, 업체 검색과 DB 등록 |
| 이미지 인식 1명 | 지원 유형과 데이터 확인, YOLO·비전 LLM 비교 검증, 분석 결과 연동 협의 |

- **11월 20일** 샘플 분석 결과로 앱과 백엔드를 연결한다. **21일** 휴대폰으로 MVP를 검증하고 시연 경로를 고른다. **22일** 선택한 경로를 다시 확인하고 제출물을 마무리한다.
- 시연 지역과 유형이 정해지면 팀이 업체명·연락처·출장 지역·작업을 확인하고, 백엔드 담당자가 몇 곳을 DB에 등록한다. 실제 업체와 샘플 업체가 각각 나오는 검색을 준비한다. 실제 업체 연락은 전화 또는 메시지 작성 화면까지 시연하고, 작성 화면에서 요청문을 확인한다.
- 실제 모델 연동을 검증하면 시연에 포함한다. 검증을 통과하지 못하면 직접 입력 경로로 시연하고, 예시 분석 결과를 보여줄 때는 샘플임을 표시한다. 원본 사진은 분석 처리에만 사용한다. 외부 비전 모델에는 동의를 받은 뒤 팀이 확인한 샘플·비식별 사진만 전달한다.

## 남은 결정과 후속 범위

- **우선 결정할 것**은 지원할 하자 유형과 시연 동네다. 창가의 곰팡이 의심 흔적은 후보로 남겨둔다. 유형을 확정한 뒤 심각도 단계 기준과 YOLO 신뢰도 기준을 정한다.
- **보류**는 재촬영과 최근 기록 목록이다. 최근 기록 목록은 같은 사례를 나중에 다시 여는 장면이 시연에 필요할 때 포함한다.
- **후속 후보**는 업체 입찰과 가격 비교, 민법 조문 조회 MCP와 RAG, 보유 도구에 따른 맞춤 안내, 기준물이나 깊이 정보를 활용한 실제 면적 측정이다.

세부 결정 이력과 검증 기준은 [프로젝트 계획](PROJECT_PLAN.md)에 정리했다. 백엔드의 현재 구현 범위와 실행 방법, 설계 문서 목록은 [README](../../README.md)에서 확인한다.
