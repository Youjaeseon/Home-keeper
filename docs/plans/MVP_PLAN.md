# 주거 하자 대응 에이전트 · 팀 공유용 MVP 계획

거주자(주로 청년 임차인)가 집에서 하자를 발견했을 때, 사진과 위치·재질을 입력해 심각도(%)·추정 원인·해결방안·재발 방지책을 파악하고, 직접 해결·임대인 점검 요청·업체 1:1 채팅 상담 및 주거 지원 사업 소식지 확인으로 이어가도록 돕는다. 지원 하자 유형은 **크랙, 벗겨짐, 곰팡이**, 시연 지역은 **용인**으로 확정했다.

## 사용자 흐름

1. **회원가입 및 탭 구조**: 일반 회원가입(`요청인` 전용) 시 `닉네임`, `ID(이메일)`, `PW`, `거주 지역`(필수), `등록 주소`(선택), `거주 형태`(`월세`, `전세`, `반전세`, `자가`, `기타`)를 입력한다. 시연용 `업체` 계정은 사전 등록한다. 로그인 후 하단 4개 탭(**`소식지` · `분석` · `채팅` · `내 정보`**)으로 이동하며 기본 시작 탭은 **`분석`**이다.
2. **소식지 페이지**: 사용자 `거주 지역`에 맞는 지자체 사업과 `전국` 정부 주거 지원 사업을 기본 노출하고(`전체 보기`/`진행중만 보기`), `거주 형태` 관련 사업은 태그·우선 표시한다. 1차 데이터는 공공데이터포털 `행정안전부_대한민국 공공서비스(혜택) 정보`(보조금24) Open API를 동기화·캐싱해 사용하며, 검증된 실제 공고 시드를 폴백으로 둔다. 마감일이 지난 공고는 `마감` 배지와 함께 흐리게 표시하고 목록 하단으로 정렬한다(열람 가능). 카드 클릭 시 앱 내 상세 요약과 `공고 원문/신청 페이지 열기` 버튼을 제공한다.
3. **하자 분석 페이지 (채팅창 없음)**: 한 화면에서 같은 하자의 사진 1~2장(전체·근접, 1장 필수·2장째 선택), **위치**(대표 선택지+직접 입력), **재질**(대표 선택지+직접 입력), **증상 메모**(선택)를 함께 입력하고 `분석하기`를 누른다. 서버가 1차 사진 분석(YOLO → 미탐지·불명확 시 비전 LLM)과 최종 진단을 연속 처리하며, 사진 분석이 실패하거나 미탐지여도 입력한 위치·재질·증상만으로 결과를 생성한다. *(설문/객관식 추가 질문은 보류로 두고 추후 논의한다.)*
4. **분석 결과 페이지**: 탐지 성공 시 사진 위에 의심 영역을 표시하고, **`심각도`(0~100% 또는 정보 부족 시 `판단 보류`, 산정 근거 포함)**, **`추정 원인`(AI 추정 안내 문구 + 미확인 정보)**, **`해결방안`(권장 대응, 처리 방법·준비물 통합)**, **`재발 방지책`**을 보여준다.
5. **다음 행동 연결**: `자가`를 제외한 임차 거주자에게는 `임대인 점검 요청문`을 제공하고(점검 권장 시 주 버튼), `업체 찾기`는 거주 형태와 무관하게 항상 이용할 수 있다. 주소·지역이 필요한 단계마다 등록 주소와 거주 지역이 현재 하자 주택에 맞는지 확인하고 다르면 수정 후 사용한다.
6. **내 정보 페이지**: 프로필(닉네임, 이메일 ID, 거주 지역, 등록 주소, 거주 형태) 조회·수정, 로그아웃, 그리고 **내 하자 분석 기록 목록**을 제공한다. 과거 기록을 누르면 해당 분석 결과 페이지를 다시 열 수 있다.

## 업체 찾기와 1:1 채팅

- 업체를 찾을 때 등록 주소와 거주 지역을 확인·수정한 뒤 `거주 지역`을 검색 조건으로 사용한다. 앱은 사진·위치·재질로 추천 작업을 미리 선택하고(판단이 어려우면 `원인 점검`과 추천 이유 표시), 사용자는 필요할 때 작업을 바꿀 수 있다.
- 해당 동네(시연 지역: 용인)로 출장할 수 있고 해당 작업을 제공하는 실제 업체를 DB에서 조회한다. 결과가 비어 있으면 `샘플` 표시가 붙은 예시 업체를 보여주고, 조회 오류는 별도로 표시한다.
- 업체 카드의 주 버튼은 **`채팅하기`**, 보조 버튼은 **`전화하기`**다(기존 외부 `SMS 메시지 보내기`는 앱 내 채팅으로 대체). 분석 결과에서 실제 업체의 `채팅하기`를 누르면 1:1 채팅방이 열리고 해당 하자 분석 요약(하자 유형·위치·재질·심각도%·추정 원인)이 자동 공유된다. `견적 요청문`은 채팅 첫 문의 초안·복사용으로 재활용한다. `샘플` 업체의 연락 버튼은 시연 안내를 띄운다.

## 역할과 시연

| 담당 | 작업 |
| --- | --- |
| 앱 1명 · React Native/Expo | 4개 탭(`소식지`·`분석`·`채팅`·`내 정보`), 회원가입·프로필, 소식지 목록(마감 흐림)·상세, 사진+위치+재질 일괄 분석 화면, 결과(심각도%·추정 원인·해결방안·재발 방지책), 업체 목록(`채팅하기`·`전화하기`), 1:1 채팅, 내 정보·기록 열람 |
| 백엔드 1명 · FastAPI/Supabase | 인증·프로필·사전 등록 업체 계정, 소식지(보조금24 API 동기화+시드, 마감 판별), 일괄 분석·진단, 기록 목록, 요청문 생성, 업체 검색, 업체–요청인 채팅 API |
| 이미지 인식 1명 | `크랙·벗겨짐·곰팡이` 데이터 확인, YOLO·비전 LLM 비교 검증, 분석 결과 연동 협의 |

- **11월 20일** 팀 회의 변경 사항을 반영한 API·화면 계약으로 앱과 백엔드를 연결한다. **21일** 휴대폰으로 MVP를 검증하고 시연 경로를 고른다. **22일** 선택한 경로를 다시 확인하고 제출물을 마무리한다.
- 시연 지역(**용인**)과 유형(**크랙·벗겨짐·곰팡이**)에 맞는 실제 업체 몇 곳의 업체명·연락처·출장 지역·작업을 DB에 등록하고 시연용 업체 계정을 준비한다. 실제 업체와 샘플 업체가 각각 나오는 검색을 준비한다.
- 실제 모델 연동을 검증하면 시연에 포함한다. 검증을 통과하지 못하면 위치·재질 기반 결과 생성 경로로 시연하고, 예시 분석 결과를 보여줄 때는 샘플임을 표시한다. 원본 사진은 분석 처리에만 사용한다. 외부 비전 모델에는 동의를 받은 뒤 팀이 확인한 샘플·비식별 사진만 전달한다.

회원 프로필·내 기록 목록 API와 모바일 등록·수정·기록 화면은 구현했고, 소식지, 실제 모델 기반 일괄 분석, 업체 1:1 채팅, 4개 탭과 회원가입 화면은 변경된 MVP 설계의 후속 구현 대상이다. 기존 코드의 AI 추가 질문 API(`messages`·`next-question`)는 MVP에서 사용하지 않는 레거시/보류 상태로 유지한다.

## 남은 결정과 보류·논의 항목

- **회원가입 등록 주소 범위**: 상세 `등록 주소`를 계속 선택 입력으로 유지할지 `거주 지역`만 수집할지 추가 논의한다.
- **설문/객관식 추가 질문 (보류)**: 분석 화면 채팅창을 제거한 대신, 추후 설문/객관식 형태의 추가 질문을 붙일지 논의한다.
- **업체–요청인 채팅 세부 사항 (보류)**: 채팅 실시간 전송 방식(FastAPI REST 폴링 vs FastAPI WebSocket vs Supabase Realtime)과 시연용 업체 계정 로그인 후 화면 구성을 팀원과 협의해 확정한다.
- **모델 기준 확정**: `크랙·벗겨짐·곰팡이`별 심각도 `%` 기준과 YOLO → 비전 LLM 2차 분석 호출 기준을 이미지 담당자와 확정한다.
- **후속 후보**: 업체 입찰과 가격 비교, 민법 조문 조회 MCP와 RAG, 보유 도구에 따른 맞춤 안내, 기준물이나 깊이 정보를 활용한 실제 면적 측정, 재촬영.

세부 결정 이력과 검증 기준은 [프로젝트 계획](PROJECT_PLAN.md)에 정리했다. 백엔드의 현재 구현 범위와 실행 방법, 설계 문서 목록은 [README](../../README.md)에서 확인한다.
