검증 문서: `docs/reports/RISK_REVIEW_EVIDENCE.md`, `RISK_REVIEW_PROMPT.md`, `RISK_REVIEW_INTEGRATION.md`

표기 규칙
- **[확인]** = 원문·공식 페이지에서 직접 확인된 값
- **[정책]** = 문헌 수치가 아니라 우리가 정한 값(가중치·상한). 문헌 근거가 아님을 명시
- **(가정)** = 도메인 추론. 문헌 근거 약함
- **(확인 필요: …)** = 존재는 확인했으나 수치·조항 미확인 → **프롬프트·출력에 넣지 않음**
- **(원문 대조 미완)** = 원문 접근 실패. 인용은 유지하되 수치를 근거로 쓰지 않음

> **개정 요지(리뷰 반영 6건)**
> ① 신뢰도 임계를 `0.40` → **40%** 로 통일(프롬프트는 퍼센트를 전달한다). ② 프롬프트는 **계산이 아니라 표 선택**(§16)으로 바꾸고, 산식은 표의 유도 근거로만 남긴다. ③ 신호를 **탐지 트랙(D) / 관찰 트랙(V) / 텍스트(T)** 로 분리하고 도달 불가 신호(C1·F4)는 프롬프트에서 제거한다. ④ 면적 구간을 **반개구간**으로 확정하고 ±1%p 완충(H3)을 프롬프트에서 삭제한다. ⑤ **판독 품질 상한 55를 모든 상한보다 먼저** 적용한다. ⑥ 법령 조항 오귀속(제36조④, 담보책임 15년, 150/180일)과 미확인 수치(±0.10mm, 32%)를 정정·강등한다.

## 1. 요약 (8줄)

1. **점수의 정본은 산식 하나이고, 노출면은 표 하나다.** 산식은 `base(30) + Σ가중치 → floor → cap → 절단`이며, 프롬프트는 이 산식으로 미리 계산한 표(§16)에서 **행 하나를 고르게** 한다. 모델에게 덧셈·뺄셈을 시키지 않는다 [정책]. 위험매트릭스(발생가능성×영향)는 쓰지 않는다 — 무작위 위해 쌍의 10% 미만만 정확히 비교한다 [Cox2008].
2. **가중치는 전부 정수다.** 그래서 `raw`가 정수이고 반올림이 발생하지 않는다. `severity_score`는 `int`만 허용되며 `float`·`"84"`·`true`·101은 모두 서버가 502로 거부한다(`_severity_score` 검증). 반올림 단계를 없애 경계(39/40, 69/70) 흔들림을 원천 차단했다.
3. **세 유형의 기준선은 모두 30점**(= 결함이 사진에서 확인됨). 30점은 low이므로, "확인됐지만 근거가 얕은" 상태가 기본값이 된다 [정책].
4. **high(≥70)는 산술로만 도달하지 않는다.** 철근 노출·실측 0.3mm·누수 동반+구조부·탈락·현재 습윤이 동반된 누수 이력 등 **비보상 floor** 를 통과해야 한다 [하자판정기준 제7조②·제8조].
5. **스케일 근거가 없으면 균열은 69 상한**이다. mm/px 확정에는 마커·광파기 같은 외부 기준물이 필수이고 [Kao2023], 자동 측정의 허용오차 수치(±0.10mm)는 **(확인 필요)** 상태다 [Pradhan2026].
6. **곰팡이는 면적만으로 high를 주지 않는다**(상한 69). high는 결로·현재 습윤 동반 누수 이력·민감 재질·다면 확산 같은 **비면적 신호**가 있을 때만이며, 재질·수분원을 판단할 수 없으면 55 상한이다 [EPA-Brief][FRAMEWORK §4.1].
7. **판단 보류(`null`)는 실패가 아니라 정상 동작**이다. 다만 보류 조건을 §8의 4가지로 한정한다. 사진 근거 없이 메모만 있는 경우는 보류가 아니라 **상한 55 + `inspection` 이상**으로 처리해 기존 테스트가 고정한 동작과 서버 규칙을 유지한다.
8. **신호는 사진 단위로 배타적이다.** 1단계 파이프라인은 사진 1장에서 `detections`(D)와 `vision_observation`(V) 중 하나만 만든다. §4-1의 트랙 배정을 어기면 모델이 없는 값을 만들어낸다.

## 2. 계산 규약 (표를 만드는 정본 산식 — 프롬프트는 이 산식을 쓰지 않는다)

```
raw   = base(30) + Σ(적용 가중치)          # 정수. 소수 가중치 금지
s1    = min(max(raw, 0), 100)             # 정수 연산으로 0~100 절단 (소수·불리언·문자열은 서버가 502)
s2    = max(s1, floor)   if floor 조건 성립
s3    = min(s2, cap)     if cap 조건 성립  # cap은 "위에서부터 우선"이 아니라 "가장 작은 cap이 이긴다"
final = min(s3, 55)      if 판독 품질 저하   # 이 상한만은 다른 모든 규칙보다 먼저 적용
band  = "low" if final < 40 else ("medium" if final < 70 else "high")
action= 표 9-1 매핑 → action 하한(A1~A5)이 성립하면 상향
```

| 규칙 | 내용 | 근거 |
|---|---|---|
| R1 유형 다중 | `suspected_types`가 2개 이상이면 **유형별로 각각 계산한 뒤 최댓값**을 채택한다. 평균 금지. `recommended_action`도 유형별 권장 중 **가장 강한 것** | [HHSRS]: 위해를 각각 채점하고 최악 위해가 상위 결정을 촉발 |
| R2 중복 가산·감산 금지 | 같은 축의 신호는 **1개만** 센다(예: 균열의 형태 신호 C8·C9·C10 중 1개, 벗겨짐의 백아화와 변색 중 1개) | [정책] 이중 가산 방지 |
| R3 floor·cap 충돌 | 동시 성립 시 **점수는 cap이 이긴다**(밴드). 단 **action은 floor 조건을 반영**해 상향한다 | [정책] §10에 사례 C-6 |
| R4 없는 값 금지 | 표에 없는 신호를 새로 만들거나, 표 값을 "대충" 조정하지 않는다 | [Stevens1946] 서열척도에 등간 정밀도 부여 금지 |
| R5 정수·null만 | `84.0`, `"84"`, `true`, `101` 은 모두 서버 검증 실패(502)다. `null`은 §8 조건에서만 쓴다 | 코드 `_severity_score` [확인] |
| R6 점수 노출 금지 | `reason`에 점수를 퍼센트·확률로 쓰지 않는다. 밴드와 근거만 서술한다. `severity_level` 키를 만들지 않는다(서버가 점수로 재계산) | [Stevens1946][OECD2008], 코드 [확인] |
| **R7 반개구간** | 구간은 **왼쪽 포함·오른쪽 미포함**으로만 판정한다(`1% 이상 8% 미만`). 경계값은 항상 높은 구간에 넣는다. ±1%p 완충(H3)은 프롬프트에서 쓰지 않는다(표 안 명시 행으로만) | (가정) 마스크 경계 판독 불확실 |
| **R8 다중 탐지 집계** | 같은 유형의 탐지가 여러 건이면 **최대 `area_ratio` 1건**만 쓴다. 합산·평균 금지. **탐지 건수는 점수에 기여하지 않는다**(참고 정보) | [정책] H1 결정성 |
| **R9 면적은 상한값** | `area_ratio`는 SAM 미완료 시 **bbox 넓이 비율**이므로 실제보다 크다. 따라서 면적은 **상한으로만** 쓰고, 면적만으로 45 초과(균열)·60 초과(벗겨짐)·69 초과(곰팡이)를 주지 않는다 | 코드 `vision.py:119`·`:204` [확인] |
| **R10 텍스트 가산 상한** | `symptoms`(자유 서술)에서 온 가점은 **합계 25점을 넘지 않는다**. 메모를 길게 쓴 사용자가 더 높은 점수를 받지 않게 한다 | [정책] 서술량 편향 차단 |
| **R11 판독 품질 우선** | 판독 품질 저하 상한(55)은 **다른 어떤 cap보다 먼저** 적용한다. 근거는 필드값(`상태: failed`, `판독 불가:` 줄)으로만 인정하고, 선명한 사진을 "흐릿하다"고 서술해 상한을 정당화하지 않는다 | [Lee2026][Pereira2020] |
| **R12 연식 추정 금지** | 건물 연식·경과년수를 추정하지 않는다. N4·Y4는 프롬프트에서 제외한다(문서 근거로만 유지) | [정책] 없는 입력으로 감점 금지 |

`build_prompt()`와 `_photo_lines()`가 만드는 문자열은 다음이 전부다. 루브릭 신호는 **여기 존재하는 값만** 쓸 수 있다.

| 채널 | 실제 전달 내용 | 사진 관측 가능 | 계측 필요 | 출처 |

| `symptoms` | 자유 텍스트(예: 검은 곰팡이 얼룩) | ✗(텍스트) | ✗ | 코드 `schemas.py:63` [확인] |

| 스케일 기준물·실측값 | **전달되지 않음**(전용 필드 없음) | ✗ | ✔ | 코드 [확인] |

> **설계에 직접 영향을 주는 사실 4개**
> ① `role`이 `overview`/`closeup`뿐이라 **정면/배면 대조가 불가능**하다. 따라서 하자판정기준 제7조②3의 "관통균열"은 **현재 제품 입력으로는 원리적으로 확인할 수 없다.** C1·F4는 **프롬프트에서 삭제**하고 `unknowns` 고정 문구로만 남긴다.
> ② `area_ratio`는 **SAM 분할이 완료된 경우에만** 마스크 면적 ÷ 화면 면적이다. 동의 없음·모델 키 없음·분할 실패면 **bbox 넓이 ÷ 화면 면적**(`vision.py:119`)이며, 대각선으로 긴 얇은 균열은 bbox가 화면의 10~30%를 차지한다. 이 구분값(`segmentation_status`)은 **프롬프트에 전달되지 않는다** → `area_ratio`는 **상한값**으로만 쓴다(R9).
> ③ **`detections`와 `vision_observation`은 한 사진에서 동시에 존재하지 않는다**(`vision.py:333`의 `elif`). 탐지가 있으면 `vision_observation=None`, 없으면 `detections=[]`다. 루브릭의 면적 신호(D)와 형태·수분 서술 신호(V)는 **사진이 다를 때만** 함께 성립한다.
> ④ 위치·재질은 `/analyze`·`/diagnosis` 모두 **422로 필수**다(`records.py:740-744`, `diagnosis.py:461-462`). "위치·재질 미입력"은 도달할 수 없는 상태다.

## 4. 사진 관측 신호 vs 텍스트 신호 (트랙 배정)

### 4-1. 트랙 정의 — 사진 1장은 D와 V 중 한쪽만 준다

| 트랙 | 정의 | 해당 신호 코드 | 프롬프트 처리 |
|---|---|---|---|
| **D** 탐지 사진 | 그 사진에 `detections`가 있음 | C6·C7·N2·N3 / Z1~Z5 / M1~M5 | `area_ratio`·`confidence`만 쓴다. 형태·수분 서술은 **없다고 가정**한다 |
| **V** 관찰 사진 | 그 사진에 `vision_observation`이 있음 (`detections`는 빈 배열) | C2·C3·C4·C5(보조)·C8·C9·C10 / Z6~Z11·Z14·Y1 / W2·D1 / N3(감별) | `summary`·`approximate_location` 서술만 쓴다. 면적 밴드는 **쓸 수 없다** |
| **T** 텍스트 | `location`·`material`·`symptoms` | C11·C12·C13·N1 / Z7·Z12·Z13·Y3 / R1~R4·W1·W3·W4·V1·N1·N2 | 두 트랙과 무관하게 항상 쓸 수 있다 |
| **—** 도달 불가 | 입력에 없음 | C1·F4(관통), G-K1의 ㎡ 환산 | 프롬프트에서 **삭제**. `unknowns` 서술로만 남긴다 |

> **운용 규칙**: ① 한 사진에서 D 신호와 V 신호를 **동시에 근거로 인용하지 않는다**. ② 사진이 2장이면 서로 다른 트랙일 **수 있다**(보장은 아니다). ③ 요청한 트랙의 사진이 없으면 그 신호는 **성립하지 않은 것으로** 처리하고 `unknowns`에 적는다. ④ `탐지 건수`는 참고 정보이며 어떤 표에서도 점수에 기여하지 않는다(R8).

### 8-1. 현행 코드 규칙 (그대로 유지)

### 8-2. 보류 조건 (LLM 지침 — 4가지로 한정)

| # | 보류 조건 | 근거 | 트랙 |
|---|---|---|---|
| U2 | **전 사진**이 `상태: failed` 또는 `판독 불가:` 이고, **메모에도 확인 가능한 진술이 없음** | [Lee2026] 판독 불가 → 근거 없음 | D·V |
| U3 | 유형 감별 불가: 곰팡이 ↔ 먼지·그을음·도장 변색 / 균열 ↔ 이물질 자국 | [WHO2009], [ASTM-D3274] | V |
| U5 | 두 사진이 서로 다른 유형을 지목해 **어느 유형도 특정 불가** | [정책] | D·V |
| U6 | "무너지나요/안전한가요" 유형의 **안전성 판정 요청만** 있는 경우 | [FRAMEWORK §2.4] 구조해석 영역 | — |

> **U1 폐기(중요)**: "사진 흔적 0건 + 증상 메모만 존재 → null"은 **폐기**한다. `test_analyze_uses_llm_diagnosis_when_only_llm_is_configured`(`test_diagnosis.py:339-390`)가 같은 입력에 **medium(55)** 을 기대값으로 고정하고 있고, 서버는 증상이 있으면 강제 null을 걸지 않는다. 대신 **V0 규칙**으로 안전을 확보한다: 메모만 있는 경우 점수 상한 **55**, `recommended_action`은 `inspection` 이상, `unknowns`에 "사진 근거 없음"을 1줄 쓴다. (U4도 폐기 — 신뢰도는 D 트랙에만 있고 관찰 유형과 한 사진에서 만나지 않으므로 조건이 성립하지 않는다.)

### 8-3. `null`이 **아닌** 것 (엄격 정의 — 오보류 방지)

| 상황 | 처리 | 이유 |
|---|---|---|
| 사진 1장뿐 | score 산출(관통·대조 신호만 미확인) | 단일성 자체는 판독 불가 근거가 아니다 [Lee2026]는 분해능 한계를 말한다 |
| 사용자가 실측값을 입력 | score 산출(상한 해제) | 측정 주체가 사람 [하자판정기준] 제7조① |
| 유형 2개 이상 관찰 | 유형별 점수 계산 후 최댓값 | [HHSRS] 위해별 개별 채점 |
| 담보책임기간 경과 의심 | score 산출 + `unknowns`에 기재 | 법적 청구 가능성은 위해 축과 별개 [FRAMEWORK §5-2] |
| **증상 메모만 있고 사진 근거 없음** | score 산출하되 **상한 55** + `inspection` 이상 + `unknowns` 1줄 | 서버 규칙·기존 테스트가 고정한 동작(§8-2 U1 폐기 참조) |
| ~~위치·재질 미입력~~ | **(삭제)** 도달 불가 — `/analyze`·`/diagnosis` 모두 422 | `records.py:740-744`, `diagnosis.py:461-462` [확인] |

### 8-4. `undetermined`일 때의 출력 규약

- `suspected_types`는 `[]`(서버가 강제로 비운다).
- `recommended_action`은 **`inspection` 이상**(`provider_consult` 허용). `self_care`는 서버가 `inspection`으로 바꾼다.
- `work_type`은 `원인 점검`(서버 강제).
- `unknowns`에 **무엇을 확인하면 점수가 산출되는지** 1줄 이상 쓴다(예: "확인 필요: 근접 사진, 또는 사용자가 직접 잰 균열폭").
- `reason`에 보류 이유를 밴드 서술로 쓴다(점수·퍼센트 표기 금지, R6).

## 9. recommended_action / work_type 매핑

> **중요**: 이 절은 **LLM 지침**이다. 서버는 `band`와 `work_type`의 정합성을 검증하지 않는다(`raw_action ∈ ACTIONS`만 확인, `diagnosis.py:266`). 따라서 프롬프트에 체크리스트로 넣고, 검증은 테스트로 남긴다(§15-12).

### 9-1. band × 유형 → action

| band | 균열 | 벗겨짐 | 곰팡이 |
|---|---|---|---|
| low (0~39) | `self_care` — 벽지·도장 보수 안내 | `self_care` | `self_care` + **재발 방지 안내 필수**(A4) |
| medium (40~69) | `inspection` (A1 성립 시 `provider_consult`) | `inspection` | `inspection` (원인 점검 중심) |
| high (70~100) | `provider_consult` | `provider_consult` | `provider_consult` |
| undetermined | `inspection` **이상**(`provider_consult` 허용) | 〃 | 〃 |

서버 제약 [확인]: `ACTIONS` 3종만 허용, `undetermined`에서 `self_care`는 `inspection`으로 치환되고 `provider_consult`는 **유지**된다(`diagnosis.py:283-285`).

**action 하한(A1~A5) — 점수가 69 이하여도 올린다**

| 코드 | 조건 | 결과 |
|---|---|---|
| A1 | 균열: 진행성 **AND** 구조부 | `provider_consult` |
| A2 | 벗겨짐: 탈락으로 바탕 노출, 또는 타일 탈락 | `provider_consult` |
| A3 | 벗겨짐: 수분 동반 | `work_type`=`원인 점검` |
| A4 | 곰팡이: band와 무관하게 `prevention_tips` 1개 이상 + `unknowns`에 미측정 3항목 | 문구 필수 |
| A5 | 곰팡이 low + 비난방공간만 | `self_care` 유지 + "거주자 유지관리 영역일 수 있음" |

### 9-2. work_type 매핑 (등록 4종: 곰팡이 제거 / 균열 보수 / 벽지·도장 보수 / 원인 점검)

| 유형 | band | work_type | 근거 | 비고 |
|---|---|---|---|---|

| 균열 | high (사용자 실측 0.3mm 이상) | `균열 보수` | 제89조①1(0.3mm 이상 → 주입식) | — |
| 벗겨짐 | low | `벽지·도장 보수` | 제9조②·제34조 | — |

| 벗겨짐 | high (탈락) | `벽지·도장 보수` | 제89조④(재시공 산출) | — |

### 9-3. 제품 문구 고정 (프롬프트 본문에는 금지 규칙만 넣는다)

| 예외 | 문구 요지 | 근거 |

## 10. 경계 처리 (38/40/42, 68/70/72)

점수는 정수 가중치 합으로만 만들고, 프롬프트는 **표 선택**이다. 남는 흔들림은 ① 측정 불확실(면적·신뢰도) ② 모델의 둥근 값 앵커링 ③ floor/cap 충돌이다.

| # | 규칙 | 내용 | 근거 |
|---|---|---|---|
| H1 | 결정성 | 같은 신호 목록이면 **항상 같은 점수**를 낸다. 재생성 시 ±1~2점 손수 보정 금지 | [정책] 재현성 |
| H2 | 반올림 금지 | 39를 40으로, 69를 70으로 올리는 보정 금지 | [Stevens1946] |

## 16. 프롬프트 투입 방식 (확정)

### 16-1. 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | 프롬프트는 `§2 산식`을 **계산하지 않는다**. 아래 표에서 **행 하나**를 고른다 | 모델은 신호 판정은 잘하고 **순서**(floor→cap)는 자주 틀린다(PROMPT 리뷰 §1) |
| 2 | 여러 행이 동시에 성립하면 **가장 큰 점수**를 쓴다. 합산하지 않는다 | 합산을 허용하면 다시 산수 문제로 돌아간다 |
| 3 | 표에 없는 조합이면 **가장 가까운 행**을 쓰고, 그 사실을 `reason`에 1문장 쓴다 | R4(없는 값 금지) 유지 |
| 4 | 표 값은 아래 **파생 규칙**을 표보다 먼저 적용해 덮어쓴다 | 판독 품질(55)·메모 가점 상한(25)은 신호별 가산이 아니라 전체 상한이다. **단 C13(사용자 실측) 행은 예외** — §8-3이 상한 해제를 규정하고 §12 C-8 기대값이 70이다 |
| 5 | 표와 §2 산식이 다를 수 있다. **표가 우선**하며, 밴드는 반드시 같아야 한다 | 차이는 §16-3에 기록. 밴드가 갈리면 표를 수정한다 |
| 6 | 표·규칙·금지 목록 어디에도 **조문·표준번호·기준 수치(0.3mm·20%)를 쓰지 않는다** | 숫자를 주면 모델이 그 숫자를 측정값처럼 인용한다(PROMPT 리뷰 §3) |
