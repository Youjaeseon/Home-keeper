# 커밋 규칙

이 저장소는 팀 협업과 변경 이력 추적을 위해 Conventional Commits 기반의 한국어 커밋 메시지 규칙을 따릅니다.

## 기본 형식

```text
<type>(<scope>): <제목>

- <변경 내용 요약 1>
- <변경 내용 요약 2>
```

- 스코프가 불필요할 때는 `<type>: <제목>` 형태로 생략합니다.
- 본문은 선택 사항입니다. 제목과 본문 사이에는 빈 줄을 한 줄 둡니다.

## Type 목록

| Type | 설명 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 추가·수정 |
| `refactor` | 동작 변경 없는 코드 구조 개선 |
| `test` | 테스트 추가·수정 |
| `chore` | 의존성, 빌드, 환경 설정, 도구 변경 |
| `style` | 포맷팅 등 코드 의미 변화 없는 스타일 수정 |

## Scope 기준

모노레포 구조에 맞춰 변경 영역을 구분할 때 사용합니다.

| Scope | 대상 영역 |
| --- | --- |
| `api` | FastAPI 백엔드 (`apps/api`) |
| `mobile` | Expo 모바일 앱 (`apps/mobile`) |
| `monorepo` | 루트 워크스페이스·공통 스크립트 (`package.json` 등) |
| `project` | 저장소 전반 환경·Git 설정 (`.gitignore` 등) |
| 생략 | `docs` 커밋 또는 특정 영역에 국한되지 않는 작업 |

## 작성 원칙

- **제목**: 한국어 명사형이나 간결한 서술(`... 추가`, `... 수정`, `... 문서화`, `... 반영`)로 50자 내외로 작성하며, 끝 마침표(`.`)는 생략합니다.
- **본문**: 변경 배경이나 핵심 항목이 여러 개일 때 `- ` 불릿 리스트로 작성하고 마침표를 생략합니다. 단순한 변경은 본문을 생략할 수 있습니다.
- **논리적 단위 분리**: 백엔드(`feat(api)`), 모바일(`feat(mobile)`), 의존성(`chore(mobile)`), 문서(`docs`)처럼 관심사별로 커밋을 분리합니다.
- **커밋 금지 대상**: `.env`, API 키·비밀번호·토큰 등 민감정보, `node_modules/`, `apps/api/.venv/` 등 생성물은 커밋하지 않습니다.

## 실제 저장소 예시

```text
feat(api): 프로필과 내 기록 목록 API 추가

- 본인 프로필 조회·등록·수정과 지역 목록 API 추가
- 본인 하자 기록 요약 목록과 진단 의심 유형 추가
- 프로필·지역·목록 DB 마이그레이션과 회귀 테스트 추가
```

```text
feat(mobile): 프로필 등록과 내 기록 목록 화면 추가

- 프로필 등록·수정과 거주 지역·형태 선택 화면 추가
- 홈에서 프로필 확인 후 분석 시작, 기존 목록 결과 재열람 연결
```

```text
chore(mobile): 사진 선택 의존성 추가

- 사진 1~2장 선택 화면에 필요한 expo-image-picker 추가
- npm lockfile 갱신
```

```text
docs: 프로필과 내 기록 목록 구현 상태 문서화

- 프로필·지역·내 기록 목록 API와 화면 구현 범위 반영
- 007 마이그레이션, Home Keeper 미적용 상태와 검증 결과 갱신
```
